# Database Setup Guide

## Overview

This project uses **Supabase** as the database to store job postings and skills data. The large CSV files have been migrated to the database to enable version control and production deployment.

## Prerequisites

- Supabase account (free tier is sufficient)
- Python 3.8+ with dependencies installed
- Filtered CSV files (generated by `analyze_and_filter_data.py`)

## Setup Steps

### 1. Create Supabase Tables

1. Log in to your [Supabase Dashboard](https://app.supabase.com/)
2. Navigate to **SQL Editor**
3. Run the SQL commands from `backend/create_tables.sql` (generated during migration)

Alternatively, run the migration script which will prompt you:

```bash
python backend/migrate_to_supabase.py
```

The script will display the SQL commands and wait for you to create the tables manually.

### 2. Upload Data to Supabase

After creating the tables, continue with the migration script:

```bash
python backend/migrate_to_supabase.py
```

The script will:
- Upload job postings in batches
- Upload job skills in batches
- Show progress with a progress bar
- Verify the upload was successful

**Note:** This process may take 15-30 minutes depending on your internet connection.

### 3. Verify Database

Check that data was uploaded successfully:

```bash
python backend/verify_db.py
```

Or log into Supabase Dashboard → Table Editor and verify:
- `job_postings` table has records
- `job_skills` table has records

### 4. Update Environment Variables

Ensure your `.env` file has Supabase credentials:

```env
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your-anon-key
```

## Data Filtering

The original CSV files (~1.1 GB) were too large for Supabase free tier (500 MB limit). We filtered the data to ~398 MB by:

1. Keeping only job postings that have associated skills
2. Random sampling to meet size requirements
3. Maintaining data diversity across job types

To re-filter the data:

```bash
python backend/analyze_and_filter_data.py
```

## Application Usage

The application now uses `db_data_loader.py` instead of `csv_data_loader.py`:

- **Faster startup** - No need to load large CSV files into memory
- **Lower memory usage** - Data is queried on-demand from database
- **Better scalability** - Database can handle more data efficiently

## Troubleshooting

### Connection Errors

If you see "Supabase credentials not configured":
1. Check `.env` file has correct credentials
2. Verify `SUPABASE_URL` and `SUPABASE_KEY` are set
3. Restart the backend server

### Slow Queries

If database queries are slow:
1. Verify indexes were created (check `create_tables.sql`)
2. Check Supabase dashboard for query performance
3. Consider upgrading to Supabase Pro for better performance

### Migration Failures

If migration fails partway through:
1. Check Supabase dashboard for error logs
2. The script can be re-run - it will skip existing records
3. Verify you haven't exceeded Supabase storage limits

## Files

- `backend/migrate_to_supabase.py` - Migration script
- `backend/analyze_and_filter_data.py` - Data filtering script
- `backend/app/db_data_loader.py` - Database data loader (replaces CSV loader)
- `backend/create_tables.sql` - SQL schema (generated during migration)
- `backend/data/linkedin_job_postings_filtered.csv` - Filtered job postings
- `backend/data/job_skills_filtered.csv` - Filtered skills data

## Production Deployment

When deploying to production:

1. **Environment Variables**: Set `SUPABASE_URL` and `SUPABASE_KEY` in your hosting platform
2. **No CSV Files Needed**: The application reads from Supabase, not local files
3. **Database Access**: Ensure your hosting platform can access Supabase (it's cloud-based, so should work)
4. **Row Level Security**: Tables have RLS enabled with public read access

## Cost Considerations

**Supabase Free Tier:**
- 500 MB database storage (we use ~400 MB)
- Unlimited API requests
- Suitable for development and small-scale production

**Supabase Pro ($25/month):**
- 8 GB database storage
- Better performance
- Priority support
- Consider upgrading if you need more data or better performance
